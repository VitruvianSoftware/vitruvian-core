Tools for everyone, stage E: mock-ups

Vitruvian for macOS. The GitHub feature becomes the GitHub tool from the catalog: pictures of what changes, before any code.

100%

The app's GitHub feature, fifteen files and an island page of its own, is rewritten as a tool of protocol 2 in apps/desktop/vitruvian-tool-github, listed in the catalog as "GitHub" by VitruvianSoftware. The app draws its pages: a page in the island's Tools area and an account panel in the tool's detail. In the release that offers it (3.46) the feature says so at the top of its page and hands the tool its sign-in and settings when the tool is installed; the release after (3.47) removes the feature. Every word inside a panel is the tool's own; the app's one new text is in the table at the end, word for word.

Five kinds of block: row (one per repository, tappable: it opens the repository's Actions page), heading, list (the pull requests, at most 100, a tap opens the pull request), button twice, and text when signed out. The icons are the colour's: a check, a clock, a cross, a dashed circle. The review standing on the right is the tool's word in fifteen languages; the title and the subtitle are GitHub's own words and the repository's name, plain.

Choice: Re-run failed checks re-runs the failed jobs of the default branch's workflow runs only, what the feature's Rerun did; a pull request's checks are re-run from GitHub. A failed check run that is no workflow run cannot be re-run, so the button is not drawn for it.

Alternative: a page per repository behind each row, as the feature had. One page keeps the island short and the person's pull requests on it; the repository's row opens GitHub for the rest.

Eleven of the tool's twelve preferences have a title, so the app draws them as it draws any tool's settings: a text field for a string, a switch for a boolean, a number field for an integer, in the manifest's order, each in the person's language. The twelfth, the token the app hands over, has no title and is never shown. Under them the tool's settings panel is the account alone: the GitHub CLI's login when it has one, a secret field for a token, a code. The caption says what does not move.

Choice: each mouse light is one line, green, breathe orange or breathe blue 9, the words the mouse command itself takes, instead of the feature's ten pickers. The app's hand-off writes them in that shape.

Alternative: the mouse settings inside the tool's own panel. Fields the app draws are the same controls, and they need no page from the tool; a panel block has no picker, so the feature's pickers could not have been kept either way.

e. The feature's page in 3.46, before the tool is installed

GitHub is becoming a tool from the catalog. Install it under Features, Tools from outside: your sign-in, watched repositories and mouse settings move with it, this page goes, and its island page becomes a tile on the island’s Tools page. Signing in through the browser does not move: the tool signs in with the GitHub CLI, a token or a code.

Browse Tools…
GitHub Status & Actions

Monitor CI workflows, check runs, and pull requests directly in the Dynamic Island and on your GravaStar mouse.

The one new text of the app, at the top of the feature's page, with the catalog's existing button. Browse Tools… takes the person to the Features page, where Tools from outside is. Once the tool is installed this page, the feature's row in the hub and its island page are hidden, and the switch is off: removing the tool brings them back, switched off.

Alternative: a banner in the island page too. The island is the one place a tool could nag, and the feature's page is where a person goes on purpose.

Stage C's sheet, unchanged: the entry's name, publisher, version and summary come from the signed list, which now says "protocol": "2" for this tool.
