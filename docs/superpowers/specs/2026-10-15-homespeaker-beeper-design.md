# Beeper as a third chat source for HomeSpeaker: design

Requested by James 2026-10-15 ("add beeper as well? that one has a mcp server"). Read against origin/main 5c13ad078 (home-speaker 1.19.0). Lands AFTER the 1.19.1 crash fix (branch fix/homespeaker-extension-main-thread), which changes the tool's main.swift, CommandLine.swift and conformance_test.py (new monitor-enabled end-to-end run).

## Decisions (James decided #3; controller decided the rest)

1. **HTTP, not MCP.** Call Beeper Desktop's local HTTP API directly (same server and token as its MCP at /v0/mcp; typed fields `isSender`, `mentions`, chat `type`; no JSON-RPC client in Swift).
2. **Read-only calls only:** `GET /v1/messages/search?dateAfter=…` each poll, following `hasMore` page by page with `cursor` + `direction` (in whichever order Beeper sends the page), until 200 new messages that would be spoken have been read (or 50 pages, 1000 messages, as a safety bound) (plus `GET /v1/accounts` once at start, and once more for each account id it has not listed). HomeSpeaker never sends anything but GET to Beeper; any other method is a test failure. *(Review fix round 1: the first build read one page of 20 only, so skipped Slack, unmentioned group chat and already-spoken look-back messages could push a wanted message off the page, silently.)*
3. **Duplicates (James, 22:30):** while HomeSpeaker's own Slack switch is on, the Beeper source skips Beeper's Slack chats; while its Google Chat switch is on, it skips Beeper's Google Chat chats. **Controller refinement (verified against James's accounts):** Slack is skipped per WORKSPACE — only Beeper Slack accounts whose team ID (from the account ID `slackgo.<TEAM>-<USER>`) equals the native Slack token's team (Slack `auth.test` → `team_id`, cached). If the native team is unknown, skip all Beeper Slack (safe default: never speak twice). Google Messages (`gmessages.*`, SMS/RCS) is NOT Google Chat and is never skipped.
4. **Settings:** `chat_monitor.beeper_enabled` (default false) and `chat_monitor.beeper_announce` (`direct_and_mentions` default, or `all`), read with decodeIfPresent. Token `Secrets.beeperToken` in the same 0600 secrets.json (DoorCopy copies it with the rest). Entered in the app's Settings (Beeper section: switch, Announce picker, Access token field + Save), on the extension's Settings page (blocks beeperEnabled / beeperToken / clearBeeperToken / beeperAnnounce), or `sync-secrets.sh --beeper [--item …] [--extension]` (Bitwarden item "Beeper Desktop API", custom field `token` else password).
5. **Address fixed** at `http://localhost:23373` (not a setting). Tests may override with `HOMESPEAKER_BEEPER_URL`, accepted ONLY for loopback hosts, so a token can never leave the Mac. Use `localhost`, not `127.0.0.1` (ATS on macOS 14+ refuses plain HTTP to IP literals); add `NSAppTransportSecurity › NSAllowsLocalNetworking = true` to the app's Info.plist; verify the tool binary (no Info.plist) reaches localhost in the end-to-end test.
6. **What is announced:** direct messages (chat `type == "single"`) and group messages that mention you (`mentions` contains one of your account user IDs, or `@room`); `all` announces every group message. Muted/low-priority chats left out via Beeper's own filters (`includeMuted=false`; `excludeLowPriority` default on). Own messages skipped (`sender=others` and drop `isSender: true`) when mute_own_messages. Reactions, hidden and deleted skipped; media spoken as "sent a photo" etc. Spoken line: "WhatsApp message from Alice: …" / "Signal message from Bob in Family: …"; history source "Beeper".
7. **Polling with a look-back window:** each poll `dateAfter = max(monitorStart, lastPollStart − 5 min)`; skip message IDs already seen; seen IDs stored with timestamps and pruned only when older than the window (do NOT use the existing `seen.removeAll()` at 500, which would re-speak the window). Nothing older than monitor start is ever spoken. 20 a page (API max). Only new messages that would be spoken (or whose account is not known yet) count toward a poll's budget of 200; messages already handled in the look-back, and skipped ones, do not, so a busy window is no alarm. Pages stop at 50 (1000 messages) whatever they hold. If either limit is reached with more still to read, or paging stops moving on while Beeper still says there is more (no cursor, a cursor already used, a page with nothing new), the poll error "Beeper: too many messages at once; some may be missed. Mute busy chats in Beeper." shows in the status file and on the page. *(Fix round 2: the first cap counted already-handled messages and raised the notice when nothing was missed.)* No WebSocket (at-most-once, no replay).
8. **Errors** (new ChatMonitorError cases, status file + page): `beeperTokenMissing` "Beeper monitoring is on but no Beeper token is saved." (setup problem); `beeperNotRunning` "Beeper: Beeper Desktop isn't running, or its Desktop API is off (Beeper Settings › Integrations)."; `beeperTokenRefused` (401) "Beeper: the saved token was refused. Create a new one in Beeper Desktop under Settings › Integrations › Approved connections."; 429 "Beeper: asked to slow down; skipping the next poll." (skip next poll; the words changed from "trying again next poll" to say what happens, signed off by the controller 2026-10-16); a redirect is refused, never followed; other → "Beeper: <message>". Beeper not running must not stop the monitor starting; next poll recovers.
9. **Status file additions** (optional keys): `beeper_networks` (e.g. ["WhatsApp","Signal"]) and `beeper_skipped_networks` (e.g. ["Slack (abrial)"]). Page line: "Reading Beeper: WhatsApp, Signal · Slack skipped (read directly)".

## Beeper API facts (Beeper Desktop 4.3.209, API 5.0.0; from developers.beeper.com and the local GET /v1/spec, no token used)
- Server `http://127.0.0.1:23373`; `GET /v1/info` (no auth) reports status, port, mcp_enabled, /v0/mcp, /v1/ws.
- Auth: `Authorization: Bearer <token>`; 401 body `{"message":"Unauthorized: Invalid or missing token","code":"unauthorized"}`. Token created in Beeper Desktop **Settings → Integrations → + next to Approved connections** (https://developers.beeper.com/desktop-api/auth). OAuth2 PKCE also exists (read/write scopes) — a "Connect Beeper…" button is a possible follow-up.
- `GET /v1/accounts`: accountID, bridge {id,type,provider} (4.2.785+), network, user {id,isSelf,fullName}, status.
- `GET /v1/messages/search`: dateAfter (ISO 8601, strictly after), sender=me|others|<id>, chatType=single|group, accountIDs[], chatIDs[], limit ≤20, includeMuted, excludeLowPriority, cursor/direction; no `query` → filter-only. Response: items[Message], hasMore, oldestCursor, newestCursor, chats {chatID: Chat}.
- Message: id, chatID, accountID, senderID, senderName, timestamp, sortKey, type (TEXT NOTICE IMAGE VIDEO VOICE AUDIO FILE STICKER LOCATION REACTION), text, isSender, isHidden, isDeleted, mentions (ids, @room, or null).
- Chat: type single|group, network ("display-only" — don't classify by it), title, isMuted, isLowPriority, accountID, unreadMentionsCount.
- Terms: "for personal use"; reads are local and unlimited; spec is Proprietary (https://www.beeper.com/terms) — do NOT copy it into the repo; fixtures hand-written with fake data.
- **Verified account ID shapes on James's Mac (via the Beeper MCP get_accounts, read-only):** `matrix` (Beeper itself), `gmessages.<email>/<n>` (Google Messages), `local-signal_…`, `local-telegram_…`, `local-whatsapp_…`, `slackgo.<TEAM>-<USER>` (Slack). No Google Chat account present; its bridge prefix remains unverified (classifier tries bridge.type, then account-ID prefix, then network name).
- Note for James: `/v1/info` on his Mac reports `hostname 0.0.0.0` and `remote_access: true` — Beeper's API is reachable from his local network (Beeper's setting).

## Tests
- StandInBeeper: URLProtocol serving fixtures for /v1/info, /v1/accounts, /v1/messages/search; any non-GET fails; every request must carry Bearer and target loopback. Fixtures (fake): WhatsApp DM; Signal group mention; same group no mention; Slack-bridged (team = native team, and a different team); Google-Messages SMS (must NOT be skipped as Google Chat); own message; reaction; photo; muted chat.
- Pure: classify table; duplicate rule (Slack on/off × same/different team × team unknown; Google Chat on/off); shouldAnnounce both modes; spoken line; defaultBaseURL refuses non-loopback; look-back window (late message spoken once).
- pollOnce with a stand-in announcer: the cases above; connection refused → "isn't running"; 401 → "refused"; no token → setup problem and zero requests.
- End-to-end (conformance_test.py, extending 1.19.1's monitor-enabled run): Python http.server on 127.0.0.1 random port with the same fixtures, recording method/path/auth; scratch settings beeper_enabled + slack_enabled; fake beeperToken (`# gitleaks:allow`); HOMESPEAKER_BEEPER_URL=http://localhost:<port>. Assert: tool alive and answering after >1 poll; status running with the expected skipped networks; ≥2 GETs with the fake token and no other methods; no "Fatal error" on stderr; second run with the stand-in stopped shows "isn't running". The real Beeper must never be reached (do not rely on block-network: loopback is likely allowed).
- By hand on James's Mac before release (ask first): app and extension with real Beeper: a WhatsApp DM from another phone spoken once; a bridged Slack message from the natively-read workspace not spoken while Slack is on; quitting Beeper shows "isn't running", reopening recovers.
