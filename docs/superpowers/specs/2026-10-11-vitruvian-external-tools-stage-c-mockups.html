Close

One named problem, in one sentence, straight after the folder picker. Nothing was copied and nothing changed. There are seven such sentences. The other six say: no vitruvian-tool.json; a mistake in it, with the rule it broke for whoever made the tool; it needs a newer Vitruvian; macOS has quarantined it; it is too large (256 MB or 10,000 files); or it could not be copied.

Choice: for a downloaded folder the alert shows the command that clears the quarantine and a Copy button. The app never clears it for the person, as the spec says.

Alternative: one generic sentence with the technical detail in English. Five fewer strings, and a person is told less.

The other six, word for word, each under the same title:

  • It has no vitruvian-tool.json file, so it is not a tool.
  • Its vitruvian-tool.json file has a mistake. Tell whoever made the tool: unknownService("camera")
  • It needs something this version of Vitruvian does not have: island
  • macOS has quarantined this folder because it was downloaded. Vitruvian will not clear that for you. If you trust it, run this in Terminal, then add it again: xattr -dr com.apple.quarantine '/Users/me/Downloads/deploys'
  • The folder is too large. A tool can hold up to 256 MB and 10,000 files.
  • Vitruvian could not copy the folder, or it changed while you were reading. Nothing was added.

g. Removing a tool

Remove “Deploys”?

Vitruvian deletes its copy of the tool. The folder you added it from is not touched.

Remove, Keep What It SavedRemove and Delete What It SavedCancel

Remove always deletes the app's copy of the tool. What the tool saved (its data folder and its own settings) goes only if the person picks the second button. Cancel is the default.

Choice: two buttons, not a tick box. The alert the app already uses when the island is uninstalled has the same shape, and a button names what happens.

Alternative: always keep what the tool saved, and offer "delete its data" separately. Safer by a hair, but the spec says Remove deletes what it saved after asking.

h. The privacy page's new section

Tools you add from outside

Everything above is about Vitruvian itself. A tool from outside is different. It is a separate program, made by someone else, that you chose to add from a folder in Settings under Features. Vitruvian has no store that offers tools, and it adds none without asking you first.

  • A tool can do anything Vitruvian can on your Mac. macOS treats it as part of Vitruvian. Whatever you have allowed Vitruvian, such as reading the screen or controlling other apps, the tool has too, with no prompt of its own.
  • It can read your files and use the network. It runs as you. It makes its own connections, which Vitruvian neither lists nor limits. The list of network connections above covers Vitruvian alone.
  • Vitruvian does not check what a tool does. The list a tool gives of what it uses is the tool's own statement. It is not a limit, and macOS does not hold the tool to it.
  • What Vitruvian keeps about a tool stays on your Mac. That is a copy of the tool's folder, a folder for what the tool saves, the tool's own settings, and a record of what you agreed to: the tool's name, version and publisher as the tool gave them, the folder you added it from, and when. None of it is uploaded, and none of it is in a settings backup.
  • Removing a tool deletes Vitruvian's copy of it and that record. What the tool saved is deleted too if you say so. The folder you added the tool from is never touched. Vitruvian cannot undo what a tool did while it ran.

With no tool added, none of this applies: Vitruvian starts no program of this kind. Add a tool only if you trust who made it.

This is a section of docs/PRIVACY.md, placed after the list of network connections. The app has no privacy screen of its own, so there is no string here to translate.

Choice: it says plainly that the app's promises above cover the app alone, and what the app itself keeps about a tool.

i. A tool stopped working

“Deploys” stopped working

The app's existing short on-screen message, shown for a few seconds. It appears once for each tool in each run of the app, at the tool's first crash. The row in Settings carries the state after that.

Choice: at the first crash, not when the app gives up. The spec says the person is told that a tool stopped working; the first crash is when a command they ran did nothing.

Alternative: a macOS notification, which stays in Notification Center. It needs the Notifications permission, and a tool that crashes at launch would greet the person with a banner.
