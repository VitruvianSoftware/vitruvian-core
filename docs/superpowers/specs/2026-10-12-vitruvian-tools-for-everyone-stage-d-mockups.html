Tools for everyone, stage D: mock-ups

Vitruvian for macOS. A tool that can draw: pictures of the new screens, before any code.

100%

A tool written to protocol 2 can describe a page and the app draws it, in its own style, in three places: a page in the Dynamic Island's Tools area, a section of the tool's detail in Settings, and a window. The tool sends a list of blocks; the app draws each with the controls it already has. A tool that needs more brings a web page from its own folder instead. The example tool here is "Deploys", by Acme: its name, its titles and every word inside a panel are the tool's own and are examples. The app's own words are the plan's string table, word for word: two new texts, and one the app already has.

The island draws blocks at its own small sizes: 12 point text, 13 point semibold headings, white on black, rows on the island's faint fill. The island's header still says Tools; under it the page has a back button and the panel's title from the manifest. A tap on a row or a button is a ui/event; the tool answers with the next page.

Choice: the island page lives inside the Tools area, behind a back button, the way a hosted utility (Homebrew, Window Layout) already does. Escape and the back button return to the tiles; collapsing the island closes the page and tells the tool. The island's own list of pages is not opened to tools.

Alternative: a page of its own in the island's section picker, as the design's NotchModule.tool(ToolID). That turns a fixed list of seventeen pages, saved by name in the person's layout, into an open one: thirty-seven files and every saved layout are touched for it.

The tool's Settings panel is drawn under "Settings", after the app's own switch and the settings the manifest gives a title. It is the same renderer at the standard size: the system's switch, field and text. The detail opens the panel when it opens and closes it when it closes, and Close keeps the keyboard, as today: every control of the panel is bound to the detail's one focus.

New in the app's words: Show in the Dynamic Island, the switch that answers the design's open question 4 (on by default). A tool's window panels are listed under Commands, each with the app's existing word Open.

Alternative: a tab of its own in the Features hub for a tool's panel. The detail is where a person already goes to change a tool; a second place would split its settings in two.

A window the app owns, titled with the panel's title and the tool's name under it. It is 380 points wide and as tall as its blocks, up to 560 points; past that its blocks scroll. It closes when the person closes it, and when the tool ends. A link opens through the app's open service, so it needs open in the tool's uses: without it, a click plays the alert sound.

Choice: a window opens only when the person asks: from the detail's Open, or as the answer to something they did in another of the tool's panels. A tool cannot open a window by itself.

Alternative: a window the person can resize. A blocks page has nothing to gain from width, and a fixed width keeps every tool's window alike.

The app's chrome is the window: the title bar with the panel's and the tool's names. Everything below it is the tool's page, drawn by WebKit from the tool's own folder. It may reach the app only through window.vitruvian.call, which the app passes to the tool's program, under the same uses and the same flood rule as every other request.

New in the app's words: This page could not be shown. The tool’s log, in Settings, says why. It is shown when the page fails to load, leaves its folder, or the tool does not answer in time, for a web panel and a blocks panel alike.

Alternative: show WebKit's own error page. It names a file path and an error code, and it is in English only.

Release notes

A tool's island page is a tile after the quick tools: the panel's icon and title, and the tool's badge where a quick tool shows that it is on, a count or a dot, set with ui/badge. A count over 99 reads 99+. Clicking the tile opens the page of (a). The tile is there while the tool is switched on, until the person turns off "Show in the Dynamic Island" in the tool's detail.

Choice: a tile in the same rail, so the island sizes, scrolls and lays it out as it does any tool, and the rail's saved order stays the app's own: a tool's tiles always come last and are not moved in edit mode.

Alternative: a row of its own under the rail, with a chevron. It reads more like a page that opens, but the island's height is worked out from its tiles, and a row under them would need that rule changed. Known limit either way: the arrow keys and Return move over the quick tools only; a tool's tile is reached with the pointer.

Every block may carry an id; a button, toggle, field and list must, since that is how their events name them, and a row with one can be tapped. Text a tool sends is drawn as plain text with a line limit, never as markdown and never as a link. The look is the app's: a tool chooses a style from a short list, never a colour, a font or a size.

Alternative: a stack block that holds others, for columns. It is the first step to a layout language; twelve flat kinds keep a page a list that reads well in fifteen languages and at the island's width.
