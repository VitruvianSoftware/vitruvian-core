# Extension settings and HomeSpeaker island Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Put the HomeSpeaker settings James changes often on the island, add per-network Beeper muting, and turn every extension's settings sheet in Vitruvian into one searchable page with a jump row.

**Architecture:** Five pull requests. In order: PR A (HomeSpeaker only, existing controls) ships the island additions, the Beeper network mutes drawn as plain switches, and the "Chats" rename. PR B (protocol) adds a `chips` block, a `section` flag on headings and a `help` text on controls, gated by two new feature names, in the schema, all five kits, conformance and the app's pin. PR C (Vitruvian app) draws them and rebuilds the settings sheet as one page with search and a jump row. PR C also shows each extension's settings page, and a live preview, on the Dynamic Island settings page (Task 10). PR D (HomeSpeaker) uses the chips and sends every section at once to apps that can draw it, once the SDK release from PR B is out. PR E (Vitruvian Remote) sends every section at once too; it builds against the in-repo kit, so it can start as soon as PR B merges.

**Tech Stack:** Swift 6 / SwiftUI (Vitruvian app, HomeSpeaker, Swift kit), JSON Schema, TypeScript, Python, Rust and Go kits (generated by `tools/sdk-codegen`), Bazel, SwiftPM (HomeSpeaker's shipping build).

**Spec:** `docs/superpowers/specs/2026-10-18-extension-settings-and-island-design.md`

- Every repo operation goes through Bazel targets (`//tools/worktree`, `//tools/git:commit -- --agent wren`, `//tools/git:push -- --agent wren`, `//tools/agent-app -- pr-create`, `pr-enqueue`). One worktree per PR, branched from `origin/main`.
- Never run a built HomeSpeaker binary or `swift run` against the real environment; tests use the sandboxed harnesses only (`scripts/test.sh` sets `HOMESPEAKER_BEEPER_URL=http://localhost:9`).
- Older apps and older extensions keep working: an extension never sends a block or field an app hasn't named in `initialize`'s `features`; a new heading/control field degrades to what the app draws today.
- The island and the sheet and the HomeSpeaker Mac app read and write the same saved values in `SpeakerConfig` / `ChatMonitorConfig`.
- Saved-setting keys stay as they are: `speech_length`, `quiet_hours_start`, `quiet_hours_end`, `beeper_announce`, `mute_own_messages`. New key: `beeper_muted_networks` (array of network keys) inside `chat_monitor`.

- Section rawValues stay (`general`, `speakers`, `monitor`, `agents`, `googleCloud`); only the title "Chat & Slack" becomes "Chats", everywhere it is shown (extension, Mac app tab, button "Open Chats…", help text).
- User-facing copy (exact): "Speak", "From", "Until", "Announce", "Skip messages I sent", "Networks", "Read directly", "Other networks show here once Beeper is being read.", "Search settings", "No settings match", "This page can't be searched.", jump-row group for Vitruvian's own rows "Vitruvian".
- New app strings go into `APP/Sources/Vitruvian/Core/ExternalToolStrings.swift` in every language that file carries.
- Conventional commits: `feat(home-speaker): …`, `feat(vitruvian-sdk): …`, `feat(desktop): …`. One product per PR (release-scope check).

## Review Focus

1. **Muting a network while the monitor runs** must not restart it (a restart drops messages in the gap and blanks the network list). Test in Task 2.
2. **A Beeper account with no bridge type and an odd account ID** (`gmessages.someone@example.test/0`, `matrix`) must still get a stable, well-formed key usable inside a block id. Test in Task 2.
3. **A saved quiet-hours time that isn't on the half-hour grid** (e.g. "22:15") must still show as picked on the island, not silently become "22:00". Test in Task 1.
4. **Search with no match, and search on a sheet whose settings page is a web page,** must say so instead of showing an empty sheet. Test in Task 7.
5. **An older Vitruvian (no `ui.chips`, no `ui.sections`)** gets switches and the Section pop-up (or Remote's buttons) exactly as today. Tests in Tasks 2, 8, 9 and 11.
6. **The settings preview closing a page the real island still shows** (two viewers of one page). Test in Task 10.
