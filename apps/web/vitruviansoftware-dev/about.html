What we do

Three kinds of work, one repository.

We work where developer experience, infrastructure and AI meet. Every project begins as a tool we needed for our own platform, and ships only once it has earned a place there.

  • Developer tooling. CLIs like devx and homelab that make a laptop behave like production, then reset it in one command.
  • Platform engineering. Google Cloud foundations, Pulumi libraries and a GitOps-managed Kubernetes platform, all as code.
  • Agent workflows. MCP servers, agent bridges and the identity and review tooling that make AI agents accountable contributors.
Open source

How we work in public.

The monorepo is public

Not just the libraries. The pipelines, infrastructure, agent guardrails and incident fixes are in vitruvian-core for anyone to read.

Mirrors stay honest

Each project has its own repository, exported one way on every merge. Contributions come back through review, never around it.

Incidents become checks

When something breaks we write down why, then ship the guard and the test that would have caught it. Both land in the open.

The name

Why Vitruvian.

Marcus Vitruvius Pollio wrote that architecture rests on three qualities: firmitas, utilitas and venustas. Strength, utility and beauty. Leonardo later drew his famous figure inside a circle and a square to illustrate Vitruvius's proportions.

We think software deserves the same test. It should hold up under load and under change. It should solve a real problem for the person using it. And it should be clear enough that the next engineer, human or not, can understand it and build on it.
